## 数据可信分层

1. **授权平台/商家接口**：只代表接口授权范围内的商品/商户；保留提供方、授权主体、商品 ID、SKU、地区、价格字段语义与采集时间。
2. **有正式文档的独立价格索引**：可提供历史/横向参照；注明其统计价/最终价定义、覆盖商城、更新时间、合作权限和缺项。
3. **公开商城目录**：只记目录标价/观察时间；不推断库存、运费、券后价或账号实付。
4. **联盟推广与导购数据**：用于发现商品和促销；标明推广范围/返佣关系，不当作中立的全市场样本。
5. **爆料、RSS、社区与转载**：发现机会线索，不参与可信市场价格分布；相同商家商品/转载需去重。

数据源“关注中”只表示纳入后续接入计划；只有凭据已配置、权限范围已核对、真实响应字段已验证且持续采样后才能标为“已连接”。目前工作台没有上述价格基准提供方的已连接采集器；`quotes` 不是统一历史行情数据库，不能用其空缺或聚合帖声称价伪造类别分布。

## 品类模型与价格带

每个叶子品类单独配置：

- 计价单位及可折算的规格字段（如纸品按明确抽数/卷数计算单位价）；
- 商品身份规则（精确 SKU/型号、规格组合、地区/质量等级）；
- 价格用途（商家当前报价、目录标价、独立价格索引历史、促销线索）；
- 来源覆盖、刷新时间、独立卖家/提供方、观测数量与证据完整率。

高位/中位/低位分位数只从同一身份层级、同一价格语义、同地区/质量条件、去转载且时间有效的观察计算。类目单位价只能给“同类单位价参考”，不能升级为“同款捡漏”。商品身份不匹配的问题不能靠中位数、截尾均值或 AI 分数补救；Microsoft Research 对商品报价归并的研究也把 offer-product 匹配质量视为价格历史准确性的核心条件。

初版管理页仅登记类别归一规则与来源候选，不预填人民币价格、捡漏线、90天或30天样本门槛。真实采样形成后，再固定回测集校准分位阈值和最少独立提供方数；样本不足必须输出“参考不足”。

## 当前结论（2026-10-05 按无 API 可行路径修正）

- **第一阶段不申请商业 API。** 先用已有 RSS/JSON/公开页面渠道保存的 `events` 原文快照与发布时间形成来源自述报价历史。事件内容变化会产生新的 fingerprint 快照；同一内容反复扫描只刷新最近见到时间。该历史适合发现重复出现的优惠，不是商家独立报价序列。
- 慢慢买公开历史价页官方说明支持粘贴商品链接并列出多平台覆盖；但本轮在 Chrome 匿名态提交现有真实商品线索后，页面内出现 `home.manmanbuy.com/dist/login.html` 登录框。故其官网 UI 可人工参考，但本地自动采集不能以匿名免登录为前提；不尝试绕登录或调用未公开接口。
- 正式库有大量已解析的来源声称金额，但页面刷新时仅覆盖14个有原文报价的自然日；有效实时行情 `quotes=0`。目前可用的高/中/低价分布和同款捡漏线仍无法诚实计算。
- 价格基准页当前只汇总各主题的历史金额线索、状态、采集平台数和原文日期数，并明确重复转载和来源自述边界；它不把线报当市场价，不从个人交易记录计算，也不产生统计价格带。
- 下一步只有在商品身份/规格和价格单位严格一致、优惠条件可拆、转载可去重之后，才按精确同款展示跨日期的来源自述历史分布；需要独立商家或可直接访问的历史价证据才能提高为商家行情参考。数据不够始终显示“参考不足”。
