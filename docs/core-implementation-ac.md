# 当前实施 AC

> 规则来源：[当前产品契约](current-product-contract.md)。旧的 S01—S10 长篇过程记录已归档；本页只保留仍会驱动代码变更的验收条件。

## I1：官方优惠物料入库

**实现：** `services/taobao_living_topics.py` 把每个生活品关键词保存为独立的官方来源；`services/taobao_alliance.py` 读取联盟官方物料，每页 100 条自动翻页到实际结果耗尽；`scanner.py` 保存每次扫描回执并只复审本轮淘宝来源。

1. 仅接受官方返回的商品身份和推广入口。
2. 只接受正数、可解释的推广价。
3. 需要参考价降幅、当前有效券或当前活动路径之一。
4. 没有优惠信号的普通商品价写入 `conditional` 审计，不成为默认列表行。
5. 短页、重复整页、官方结果页数上界和 1000 页安全上限必须停止并写入扫描回执，不能静默漏页或无限循环；官方 `total_results` 是审计上界，不覆盖短页结果。

**验证：** 真实 API 回放与 `tests/test_taobao_alliance.py`、`tests/test_taobao_living_topics.py` 同时通过；`source_scan_runs` 的主题、页数、停止原因和计数可复查。

## I2：价格展示

**实现：** `services/product_search.py` 和 `templates/` 统一输出报价类型。

1. 显示“淘宝联盟官方推广价”，不能写成账户到手价。
2. 条件券后价必须可由同一响应复算，并保留门槛、有效期和数量。
3. 不解释的 `final_promotion_price` 不能显示、排序或影响结论。
4. 无价记录不显示“金额未提取”来伪装成报价。

**验证：** 专项样例覆盖直接推广价、条件券价、过期券、无法解释预估价和无价拒收。

## I3：SKU 详情增强

**实现：** `services/taobao_sku_detail.py` 和 `services/taobao_sync_validation.py`。

1. 详情返回必须与官方物料商品身份一致。
2. SKU/规格/库存/价格齐全时才标记为可比。
3. 详情权限不足时写出明确原因，但保留已通过 I1 的官方优惠观察。

**验证：** SKU 成功、商品级字段、错误权限和接口回退均由测试覆盖。

## I4：维护价格带判断

**实现入口：** `services/maintained_price_baselines.py`、`routes/price_benchmarks.py` 与 `maintained_price_baselines` 配置表。

**输入：** 运营人员为一个明确品牌/商品/规格维护必要词、计价方式、基准单位、可捡漏/低位/中位/高位阈值、生效日和启用状态。数字只来自本平台维护，不从第三方或交易记录自动生成。

**判定：** 只有淘宝联盟官方推广价、品类词、全部必要词和标题中的唯一规格换算同时存在时才归一到基准单位。规则冲突、规格不明、非官方推广价和无价均返回未判定。

**验收：** 自动用例覆盖抽纸多包、容量、固定规格、缺规格、冲突、非法阈值、版本审计和列表显示；实际“按维护基准：可捡漏”标签还须由运营录入真实基准后回放对应官方物料验证。
