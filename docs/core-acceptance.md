# 核心目标、验收清单与缺陷台账

## 当前产品范围：不记录用户本人的交易

用户已明确：工作台负责发现机会、采集和核实公开来源、比较优惠与价格、给出有依据的利润估算；不负责记录用户本人的买入、持仓库存、出售、退款或实际收益。因此这些不作为平台页面、入口、核心验收项或采集阻塞条件。行情依据中的“外部已完成成交价”仍可作为市场证据，但它必须有外部来源，不是用户交易台账。旧数据库表和历史行保留兼容，不读取、不展示、不继续写入。

## 当前阶段纠正：先采集、比较与预估，再执行（2026-10-04）

用户明确纠正：当前需要把数据来源、商品、价格、利润等关键采集信息补齐并校验正确。本人实付、本人库存、实际买卖和到账属于后续操作，不能作为信息采集、市场比较或预计利润计算的前置条件。此前把交易闭环标准提前套到数据准备阶段，工作顺序错误。以下当前清单替代历史记录中“先账号结算才能比较”的优先级；历史运行事实仍保留。

当前交付应为同一个工作台中的可追溯机会资料：卖什么、哪里报价、选中规格、需要买多少、单件/整单价、优惠限制、发布时间/采集时间、同款可比价、转售参考类型、费用依据、预计利润或明确的数据缺口。没有本人购买记录也必须能持续采集和分析。公开挂牌、爆料、回收估价和已成交价格须分别标注；来源间转载不算独立证据。

预计利润 = 同一数量口径的预计出售收入 − 条件买入总额 − 买卖运费、手续费、包装等有依据的预计费用。可使用有出处的价格/费用区间，展示假设和保守情景；缺项不能按零。只有挂牌或估价时可以展示参考价差及其类型，不能冒充已成交净利。不以固定“三笔成交”或“本人结算15分钟内”阻断前期行情收集。后续执行前再核实本人资格、实时结算与可购数量，执行后再记录实际收益。

## 最高优先级：发现并比较最优惠、最合适的资源（2026-10-04）

核心交付是帮助用户找到满足用途和条件、总成本更低的方案。渠道数量和页面数量不作为完成标准。家用耗材、餐饮、个护、母婴、宠物、出行、数字权益及数码均属于候选覆盖面；商品报价、直接免费、付邮、试用、积分、优惠券、抽奖及返后须分开，不用标价大小混排。

处理顺序固定为：扩大有效来源覆盖 → 保留来源/时间/原文与活动链接 → 提取同款规格、包装、买几件和整单报价 → 分开新人/会员/地区/限时等条件 → 补齐运费、积分消耗、返款条件和叠加规则 → 同口径比较当前/历史价格 → 展示范围内更便宜的适用方案。转售再单独引入退出参考与预计费用，不能把自用省钱直接叫利润。

验收时必须回答：什么商品/权益、哪里获得、一次实际需要支出多少、得到多少、需要什么条件、相较哪些同口径方案更便宜、数据何时发布/复查、未覆盖哪些渠道。不能以本人已下单/已有库存为开始比较的条件；也不能以一个低价标题或“原价”宣称全网最低。

C02—C06下一核心工作：形成可追溯的公开报价记录，严格按同款与数量口径归组，明确可比/不可比原因；有缺口继续自动补采可用公开来源。当前本轮只完成来源扩充、机制/主题过滤与持续采集，完整同款比较、条件叠加和利润区间仍未完成。

## 2026-10-04 公开行情利润模式与优惠同步状态

#### 这条金额为何能算、又为何不能当实付价

解析器把“5.1-5优惠券”识别为满 5.1 减 5，把“首购-1”识别为首购礼金候选。用来源所述秒杀价 7.10 元计算，在暂按首购抵扣 1 元、满减券能用于此订单、并按相应顺序满足门槛的前提下：

- 券先用：7.10 − 5.00 − 1.00 = 1.10 元；券抵扣前 7.10 元，超过 5.10 元门槛。
- 首购礼金先用：7.10 − 1.00 = 6.10 元；再减 5 元后为 1.10 元；假设优惠门槛按此时金额判定，仍超过 5.10 元。

两条算式都只是解释“来源为什么会声称低至 1.1 元”，不是优惠规则已核实。原文未给“首购-1”的币种和可抵范围，计算为了回放来源口径暂按人民币 1 元；领券方式含砸蛋，不能保证抽中；账户/首购资格、商品/SKU适用、平台门槛口径、叠加规则均未有商家公开依据；运费未知，系统不按 0 元填入。因此系统不能把 1.10 元输出成已核实最终应付、必买优惠或捡漏价。

#### 通用代码修复，而非给纸品或单条记录写死规则

- 优惠解析补足“满额-减额优惠券”及“首购-金额”两类常见来源简写；保留原始命中、上下文、规则机制、单位证据与未核验状态。
- 修正简写识别的边界：模式只在同一行消费券上下文，不能跨行把下一条转载文本或“满件折 1-0.85”等数字误解析为券。包装、型号数字仍不应变优惠。
- 把首购礼金呈现为优惠候选，不再落入折扣率分支；原文没有人民币单位时，在页面明示“仅按人民币元作条件试算”。
