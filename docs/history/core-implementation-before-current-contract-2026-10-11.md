# 多平台机会工作台：核心落地步骤与逐项验收

本文补充[产品概述](product-overview.md)的 S01—S10，作为后续开发和验收的逐条依据。**S01 淘宝联盟官方物料采集和官方推广价展示已接通；S03 SKU、规格、库存和结算核验仅作为增强证据；S04 独立同款比价仍未通过。** 官方物料的推广价不是账号结算价，缺独立基准时不能写成捡漏。源码基线核对日为 2026-10-11；工作分支 `feature/bootstrap`，包含未提交改动，不能只靠提交号重现该工作树。

## 2026-10-11 S04：官方物料优先准入纠正（PASS，捡漏判定仍为 PARTIAL）

### 调查实际

对当前已配置 AppKey 的只读实测，`taobao.tbk.dg.material.optional.upgrade` 返回 20 条物料，20 条带官方促销信号。首条返回参考价 `19.90`、官方推广价 `10.01` 和有效路径“满 7 减 5”。同一 AppKey 的两条 SKU 详情接口仍返回 `isv.permission-api-package-limit`。因此此前“默认列表必须等待 SKU 详情”的产品门槛与当前可用的官方物料证据矛盾。

### 实施与判定

1. 官方物料满足商品身份、官方推广入口、当前来源快照、正数推广价，并有参考价降幅、当前券或当前促销路径之一时，进入默认列表，标签固定为“淘宝联盟官方推广价”。
2. SKU 详情仅补充规格、库存和同款可比性；详情接口受限时，官方物料仍可展示，但不能参与同款比较、市场基准或捡漏结论。
3. `final_promotion_price` 只有能由当前已返回路径逐项复算时才显示。无法解释的预估后价不显示为到手价，也不参与排序。

### 实践检验

定向回归 44 项和全量 284 项均通过。现有数据库页面回放使用新准入逻辑：淘宝官方推广价会进入默认商品列表；页面不出现“已证实捡漏”。本地 Web（PID 11927）与淘宝 worker（PID 11953）已从本次源码重启；`/health` 返回数据库正常，默认淘宝列表实见 40 条官方推广价，#1194 详情页显示“淘宝联盟官方推广价 / 官方优惠观察”。

### 修改判据

若官方物料缺商品身份、推广入口、推广价或当前优惠信号，则回到线索池；若出现无法解释的价格差额，则仅保留原始字段和路径，不显示该预估价。若后续 SKU 详情返回完整绑定字段，只提升比较能力，不改变官方物料已可展示这一结论。

## 2026-10-11 S03：双详细接口交叉核验（PARTIAL）

### 调查实际

官方当日文档显示 `taobao.tbk.item.details.upgrade.get` 和 `taobao.tbk.item.details.get` 都接受字符串 `item_id`、支持 `biz_scene_id=1` 动态 ID场景，并都输出 SKU 列表、规格、库存与 SKU促销价。`taobao.tbk.item.info.upgrade.get` 只作商品级信息诊断，不能生成 SKU 报价。

### 实施与判定

1. 按升级详细版、旧详细版的顺序请求同一官方物料 ID；升级版已完整绑定 SKU 时不重复请求旧版。
2. 只有响应中的回显商品 ID唯一匹配请求 ID，且同一响应给出 `sku_id`、正库存和 SKU价格，才写 `field_state=bound`。多 SKU 时还必须有本 SKU 的属性标签；仅返回一个 SKU 而未给属性时可保留该 SKU 的当前报价，但标为“不可跨商品比价”，不从标题补造规格。
3. 每次尝试保存方法、本地结果和官方 `sub_code`。简易详情接口、商品级金额、推广短链均不能进入报价、排序、比价或捡漏计算。

### 实践检验

对一条当前官方物料做有界人工复查：两个详细接口均返回 `isv.permission-api-package-limit`。持久化结果为 `access_restricted`、`conditional`、无 `advertised_cents`，默认淘宝优惠列表仍排除该记录。定向回归覆盖双接口调用顺序、旧版详细响应的 SKU 解析、双权限限制审计、商品级隔离，以及“唯一 SKU 无属性仍保留金额、但禁止市场基准”的分支。

### 修改判据

只有任一详细接口在真实物料上返回同 ID 的完整 SKU字段，才进入下一步 SKU报价、条件和基准验收；再次得到相同权限子码时，问题归为 API 包权限，不通过反复采样或用商品级金额绕过。

### 唯一 SKU 的金额修正（2026-10-11）

旧详细接口有“同一 SKU 现价低于该 SKU 参考价”的返回形式，它不一定给 `sku_final_promotion_price`。代码此前在该分支错误选择缺失的预估价，导致 `advertised_cents=null`；现已改为“有预估价取预估价，否则保留绑定的 SKU现价”。唯一 SKU没有属性列表时，不猜测包装/型号，只保存 `sku_binding_mode=sole_sku` 与 `specification_comparable=false`。它可作为该 SKU 的优惠观察，不能用于同款市场基准、跨平台比较或捡漏结论。定向 44 项、全量 284 项测试和本机网页/worker 重启验证通过。

## 2026-10-11 同步后逐条核验回执（PARTIAL）

### 1 调查实际

旧 `taobao-worker` 在每轮官方物料扫描后，只从全局详情队列挑选最多 `TAOBAO_DETAIL_BATCH_LIMIT` 条。因此它可能先处理历史积压，无法证明刚刚同步的每条物料已走到 SKU、库存、价格和优惠路径核验。渠道页只显示原始/解析/优惠候选/拒绝四项采集计数，也没有“本轮记录最终核验到哪里”的可审计结果。

### 2 已实施办法

- `scanner.scan_source` 现在为淘宝联盟运行返回并保留本轮全部机会 ID，区分新建与重复观测；重复记录仍指向原有机会，历史不删除。
- `services/taobao_sync_validation.py` 以本轮 ID 为唯一范围分批调用 SKU 核验。它不把重复记录强制越过 24 小时官方权限冷却期，但会把已留存的核验状态、缺少的商品身份/SKU/规格/库存/报价绑定/优惠依据和下次复查时间写入本轮运行回执。
- 定时任务、命令行 `scan`、渠道页的单项扫描、批量扫描和全量扫描均复用同一回执流程。优惠依据可以是官方当前促销路径，或同一SKU可复核的参考价高于当前价；“SKU证据完整”只是六项字段都齐，不等于默认商品列表准入或捡漏结论。

### 3 验收标准

| AC | 输入 | 预期结果 | 失败判据 |
|---|---|---|---|
| S03-07 | 一轮官方物料同步，含新记录和重复记录 | 运行回执列出每个本轮机会 ID；新记录进入定向详情核验 | 回执中出现未归属机会 ID，或详情队列处理了其他来源记录 |
| S03-08 | 已被 `permission_unavailable` 冷却的重复记录 | 回执显示当前限制、具体缺项及下次复查；本轮不重复请求官方 API | 将旧状态写成“本轮已通过”，或绕过冷却反复请求 |
| S03-09 | SKU绑定响应 / 商品级响应 / 权限限制响应 | 回执分别显示完整 SKU 证据 / 缺 SKU字段 / 接口限制；默认优惠准入仍复用搜索页规则 | 商品级金额或空字段被回执当作可用报价 |

### 4 当前边界

这项改动保证“每条本轮物料都有可追溯核验结果”，不让同步成功掩盖详情核验缺失。它不能令官方接口提供当前尚未返回的 SKU 字段；真实 SKU数据继续是 S03 的外部阻塞，市场基准与捡漏判断继续未通过。

### 5 真实运行验收（2026-10-11）

- 使用当前 `feature/bootstrap` 源码启动本机网页服务和唯一淘宝 worker 后，对正式官方来源 #44 执行运行 #15：原始 20 条、解析 11 条、官方优惠候选 11 条、拒绝 9 条；本轮新增机会 11 条。
- 回执精确覆盖这 11 条：`synced_count=11`、`attempted_count=11`、`accounted_count=11`、`unaccounted_opportunity_ids=[]`、`complete=true`。因此“同步后都有核验结果”这一机制验收通过。
- 11 条的详情状态均为 `access_restricted`，SKU 接口状态均为 `permission_unavailable`，缺 SKU、规格、库存、报价绑定和优惠路径。它们的自动状态是 `conditional`，但实测没有任何一条出现在默认淘宝优惠列表；实时 `/sources` 页面显示同一回执和每条具体缺项。
- 定向 41 项与全量 280 项 unittest、受影响模块编译、`git diff --check` 均通过。外部接口仍未返回可绑定 SKU 的字段，所以 S03/S04 与捡漏结论保持 PARTIAL；本段不能被解释为 11 条可买优惠。

## 2026-10-11 现行官方动态商品 ID 链路回放与 S03 隔离（PARTIAL）

### 1 调查实际

- 当前官方物料接口是 `taobao.tbk.dg.material.optional.upgrade`。本轮真实回放取得 5 条原始物料、2 条可解析的淘宝推广物料和 2 条带官方优惠路径的候选；推广入口为 `s.click.taobao.com` 短链，物料同时返回当前“新商品 ID”。
- 今天的 `taobao.tbk.item.details.upgrade.get` 文档明确：`item_id` 是字符串，`biz_scene_id=1` 用于动态 ID 转链场景。因此物料新商品 ID应直接送入该升级详情接口；`taobao.tbk.item.click.extract` 只用于“只有链接、没有物料商品 ID”的反查，不能作为本产品主链路。用两条真实物料的新商品 ID直调升级详情接口，均返回 `isv.permission-api-package-limit`，无详情记录和 SKU 列表。

### 2 分析矛盾

此前代码在升级详情失败后尝试旧详细/简易商品接口。这样会把现行动态 ID链路的失败误导为“还有接口可兜底”，而旧响应没有 SKU、规格、库存和价格绑定，不能满足 S03。

### 3 已实施办法

- `services/taobao_alliance.py` 保留物料新商品 ID、官方推广入口和优惠路径。`detail_item_identity` 只接收物料响应中的 ID，标题、跳转页和价格都不能推断商品 ID。
- 这一历史记录中的“只调用升级详细版”已由本文顶部的双详细接口复核取代：现行实现按升级详细版、旧详细版交叉核验；简易商品接口仍不参与 SKU报价，避免把商品级金额伪装成 SKU报价。
- 自动任务记录“官方升级详情接口未开放，尚未取得 SKU/规格/库存/价格绑定”。该状态保持 `advertised_cents=null`、`promotional_candidate=false`，按 24 小时重试；详情页显示物料 ID来源和实际官方方法，默认优惠列表继续排除该记录。

### 4 实践检验

- 定向回归覆盖物料新商品 ID、SKU详情成功、详情权限拒绝不回退、商品级响应隔离和默认列表排除；`tests.test_taobao_alliance` 共 37 项通过。完整套件、服务重启和页面回放待本轮代码完成后记录。
- 真实只读回放证实物料搜索已可用，并在正确的动态 ID场景直接复现升级详情接口限制。回放响应未写入业务库。

### 2026-10-11 定时采集与核验闭环

- `app.py taobao-worker` 现在每分钟检查已启用的淘宝联盟来源是否到期；到期后按来源配置间隔执行官方物料扫描，并仅对淘宝联盟记录运行 SKU 详情核验。不会借由此任务请求其它来源。

- 本地当前 worker 已启动。立即回放 #14 实际取得 20 条原始物料、10 条解析淘宝物料、10 条促销路径候选、拒收 10 条，并执行 20 条来源限定的详情探测。默认合格优惠为 0；在“当前线索池”可以查看这些官方候选及其缺失证据。

### 5 总结修正

S03 仍为 **BLOCKED**，当前阻塞是当前 AppKey尚未获得升级详情接口返回 SKU字段的能力。不能用物料商品级金额推进 S04、单位价、同款比较或捡漏结论。接口返回同一商品 ID、SKU、规格、库存和价格路径后，才执行 AC-S03-01 至 AC-S03-06；此前不能放宽默认上架规则。

## 2026-10-10 官方优惠路径回放与真实采集（PARTIAL）

- 问题与证据：正式库来源 #44 的首轮 20 条官方搜索原文中，6 条淘宝店商品带 `final_promotion_price` 和逐项 `final_promotion_path_list`，旧适配器只保留 `reserve_price/zk_final_price`，因此仅 2 条被认作优惠候选。例：公开推广价 ¥12、官方预估优惠后价 ¥1.91、两项路径优惠 ¥4.80 + ¥5.29，接口还注明“需凑单”。
- 修复：保留原始预估价、优惠路径和凑单提示；仅当全部路径在采集时有效、优惠金额合计与公开价到预估价差额一致时，认作**优惠线索**。公开报价仍为 `zk_final_price`，预估价不再扣一次券，也不充当结算实付价。无效/过期/金额不符路径不晋级。
- 回放：首轮原始快照 20 条、可解析 6 条，旧规则优惠候选 2 条，新路径候选 6 条。最新代码再向官方接口真实采集一轮：原始 20、解析 11、带优惠依据 11、拒收 9；本地来源 #44 新增 11 个观测。结果随接口实时返回变化，不保证每轮固定 11 条。
- 同步修正：同来源同官方商品 ID 的不同推广短链仅最新观测列为当前，旧观测留库；无已绑定规格时不从标题计算纸品每包/百抽价。页面显示“联盟采集时间”，不再误写“原文发布时间未知”。269 项隔离库回归和 `git diff --check` 通过。
- 未通过：当前官方结果的报价仍是商品级公开推广价，未取得 SKU 对价、可执行凑单方案、账号结算价或独立同款基准。S03/S04 及捡漏结论继续 PARTIAL/NOT_RUN；不能把 11 条线索称为 11 条已证实低价。

### 默认上架越级修复

- 发现：默认 `offers` 视图此前只检查 `promotional_candidate`，把“联盟存在优惠路径”直接当作商品列表准入；这绕过了本文件 5.2/S08 要求的商品身份、选中规格、整单金额、时效及条件计算，因此不符合产品定义。
- 修复：新增统一 `promotion_admission`。默认公开优惠必须同时满足优惠证据和 `assess_readiness.search_ready`；未取得报价对应 SKU/规格的联盟结果降为 `promotion_clue`，只留当前线索池。公开优惠与捡漏继续分层，代码不会在没有基准 Decision 时生成捡漏候选。
- 实测：关键词“抽纸”、淘宝范围的当前正式库有 22 条联盟优惠信号，但 0 条取得报价对应的明确规格，因此默认页显示公开优惠 0 条、捡漏候选 0 条；22 条原始记录仍在当前线索池，不删除历史。全量 269 项回归通过，浏览器实际页面已核对。


## 2026-10-09 S01/S02 首轮实现与实测（PARTIAL）

### 续查：官方活动页与无人值守采集边界

| 参考价缺失会导致有效优惠漏失 | 同一真实响应仅隔离参考价校验，检查身份、价格、券条件及对应SKU是否仍足够 | 若真实输入也缺关键规格或优惠条件，则不能认定放开参考价就能产生有效优惠；修复只保留候选。 |
| 0/null混淆可能影响通知/展示 | 重放两种0及null，追到统一准入、详情、通知消费端 | 若下游已独立识别领完，影响范围应缩小为解析/展示不一致，不声称实际发错优惠。 |
| 纯日期兼容能恢复记录 | 核对来源契约，再回放原始日期及开始/截止边界 | 没有日期语义或记录已过期时仍不得恢复有效优惠；兼容不等于延长时间。 |
| 修解析能改善真实产出 | 固定一批真实输入，逐条比较改前/改后可用报价及有效优惠数量 | 产出不增加时不能宣布核心优化成功，应检查缺失字段、来源实际无优惠或准入的下一阻断点。 |

#### 5 总结修正

此次将优先次序修正为：**先核对实际运行链路与真实输入 → 再量化解析损失 → 修确认缺陷 → 验证有效优惠和可比结果**。S01/S02可以独立调查，但不能以S02模拟通过代替S01真实发现。

保留68项AC作为断言清单，停止把“清单写得多”当作可行性证据。本轮6例是现有实现的基线观察，并未完整执行相应AC；S01—S10的实现验收状态仍不提升。下一次执行首先确认实际服务DB与来源状态，然后用真实输入决定先改适配器还是先解决来源可达性。
