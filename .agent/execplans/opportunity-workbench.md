# 淘宝生活品主题配置与全量同步

## Purpose / Big Picture

把当前固定查询词“抽纸”的单一淘宝联盟来源，改为可维护的生活品主题集合。运营者在“渠道管理”中能看到并维护每个主题的关键词、启停、同步频率和最近一次官方采集证据；后台 worker 仍使用既有到期调度，因而会自动同步所有已启用主题。

完成后，至少覆盖纸品、饮用水、大米、面粉、食用油和洗衣液。每条进入默认列表的记录仍必须通过现行产品契约的“官方优惠观察”准入；主题扩展不降低价格、优惠信号和官方入口要求。

## Facts, Decisions and Constraints

| 项目 | 结论 | 依据 |
|---|---|---|
| 当前单一主题 | #44 URL 为 `q=抽纸&page_no=1&page_size=100&max_pages=all` | 当前 SQLite 来源快照；`docs/current-product-contract.md` |
| 多主题调度 | worker 每分钟检查到期来源，扫描器可按 `method=taobao_alliance` 扫描所有到期行 | `app.py:run_taobao_cycle`、`scanner.py:scan_all` |
| 证据规则 | 主题是发现范围，不能让普通商品价进入默认优惠列表 | `docs/current-product-contract.md` 第 2、3 节 |
| API 约束 | 单来源每轮自动全量翻页；官方 API 有实际配额和瞬时错误风险 | `services/taobao_alliance.py` |

**决策：** 不新增平行“主题状态”表。一个主题对应一条 `sources` 记录，来源行已具备关键词 URL、开关、频率、状态和采集历史。新模块只负责主题目录、规范 URL、归属识别和幂等初始化，防止两份配置漂移。

**默认范围：** 首批核心生活品主题为纸品、饮用水、大米、面粉、食用油、洗衣液；后续可由同一界面新增主题、启停或调整频率。关键词变更采用新来源替代旧来源，保留旧来源历史。新建主题保留独立 60 分钟频率，已有 #44 保留现有历史和频率。

## Plan of Work

### 1. 主题目录与来源归属

新增 `services/taobao_living_topics.py`：定义主题 key、名称、关键词和分组；从关键词构造唯一的官方 TOP 搜索 URL；读取来源时识别现有主题；初始化时采用相同关键词的既有来源，缺失才创建。

**验收：** 对“抽纸”返回 #44 而非插入重复行；为其余五个关键词生成同一官方端点、`page_size=100`、`max_pages=all` 的 URL；非法/非官方 URL 不被主题配置接受。

### 2. 配置页面和操作路由

来源页增加“淘宝生活品主题配置”，展示主题、关键词、状态、频率和最近成功时间。初始化动作是幂等的；每个主题复用已有来源启停、频率和单次检查能力，避免复制扫描逻辑。

**验收：** 初始页面显示六个主题和“#44 已归入纸品”；二次初始化不增加来源数；管理操作仍受 CSRF 保护。

### 3. 调度与数据准入回归

确认新主题是独立 `taobao_alliance` 来源，现有 worker 在它们到期后会自动扫描。保留 `has_current_promotion_signal` 和默认列表筛选，确保拓宽主题不会把普通目录价写入默认列表。

**验收：** 调度测试能选出两个不同主题的到期来源；带价格但无优惠信号的官方物料仍为 `conditional`；全量测试通过。

### 4. 真实数据验证与交付

使用已配置的本机凭据，对新增主题逐个请求官方 API 的单页小样本，记录原始条数、解析条数、带优惠信号条数、API 错误和时间。验证通过后启用相应主题，由 worker 按配置持续全量同步；失败主题保留为待处理，不伪造成功。

**验收：** 交付一张主题级真实回执表；每一个“已启用且健康”主题都有本轮官方 API 成功证据。无法返回的主题明确标记失败或待配置。

## Validation and Acceptance

1. `python -m unittest discover -s tests` 通过。
2. 新主题服务和来源路由的专项测试通过。
3. 本机服务 `/sources` 显示实际主题配置，且现有 #44 没有重复。
4. 从官方 API 回放至少一次每个主题；不以页面、Mock 或历史数据代替。
5. 默认优惠列表继续排除无优惠信号的记录。

## Recovery / Idempotence

- 初始化用关键词匹配，重复执行不会新增同关键词来源。
- 主题暂停只修改对应来源的 `enabled/status`，不会删除任何已采集事件。
- 如果官方接口出现配额或远端错误，保留上一次成功数据和扫描回执，下一调度周期按既有失败重试规则执行。

## Outcomes and Retrospective

- 实现：`sources` 是唯一的运行时主题配置。预置主题只是首次初始化目录；运营者可在来源页新增自己的关键词，独立维护频率与启停，不需要发布代码。禁止原地改写旧关键词，避免历史观察丧失来源含义。
- 实测：饮用水（399 / 395 / 391 / 4）、大米（199 / 197 / 191 / 2）、面粉（896 / 886 / 793 / 10）、食用油（99 / 92 / 91 / 7）、洗衣液（699 / 689 / 670 / 10），依次为原始 / 解析 / 优惠信号 / 拒收。每项来自本机已配置联盟凭据的官方 API 运行。
- 分页修正：官方 `total_results` 不是当前应用可访问物料数。现实现保留它作为审计上界，并在短页、重复页或官方页上界时停止，避免假称“全站全量”。
- 性能修正：淘宝 worker 的复审现在仅处理淘宝来源；此前它会对所有历史连接器执行全库复审，造成新的官方同步被无关历史记录拖慢。普通全渠道 worker 保持原来的全量复审行为。
- 验收：`PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B -m unittest discover -s tests` 通过，297 项；当前变更已完成提交前检查。
