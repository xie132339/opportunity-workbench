# 闭环淘宝官方优惠与维护价格带

This ExecPlan is a living document maintained according to `~/.codex/PLANS.md`.

## Purpose and observable outcome

让工作台持续展示淘宝联盟可解释的官方优惠观察，并在运营录入具体商品、规格、单位和固定价格带后，准确显示“按维护基准”的价格判断。用户可以在本地列表和详情页看到原始官方入口、官方推广价、命中的基准版本和结论；不满足规则时保留官方观察且不猜测。

## Scope, constraints, and assumptions

- 仅处理当前淘宝联盟第一方物料与本地维护价格带，不恢复已停用的第三方爆料来源。
- 任何“可捡漏”结论仅表示低于运营维护阈值，不能称为账号结算价、全网最低价或利润。
- 真实价格阈值必须由运营维护；代码和模型不得编造。
- 在 `feature/bootstrap` 开发，绝不修改受保护分支；保留未跟踪 `docs/evidence/`。

## Context and orientation

- `services/taobao_alliance.py` 读取官方物料，`scanner.py` 扫描、写入原始事件和机会，`autoreview.py` 输出官方优惠观察。
- `services/maintained_price_baselines.py` 按标题必要词、规格和单位计算本地价格带；`routes/price_benchmarks.py` 管理版本化基准；`routes/search.py`、`routes/opportunities.py` 展示结论。
- 现有页面实测显示维护基准为零，淘宝默认公开优惠为零；但本轮 worker 原始日志出现官方物料响应。因此先恢复“官方原始物料到默认列表”闭环，再做真实基准回放。

6. 性能修复不改变“官方优惠观察”准入或维护价格带判断：页面只删除不参与展示结论的重复全量计算；来源、金额、条件、规格和价格带仍按原有业务规则判断。

## Surprises and discoveries

- 2026-10-11：直接 `sqlite3 -readonly` 被执行环境拒绝打开数据库；通过同一命令会话启动的 Flask 页可以读取现有数据库。
- 2026-10-11：执行器会在命令结束后清理后台子进程，网页和 worker 的验收须在同一 shell 会话中完成。
- 2026-10-12：浏览器客户端超时不会取消 Flask 正在运行的 CPU 计算；旧 `/verification` 请求可继续占用 Web 进程，连带拖慢后续导航。因此不能仅调大浏览器/HTTP 超时，必须删除请求路径上的全库计算。

## Decision log

- 2026-10-11：先调查官方物料到公开优惠观察的链路，再录入价格带。理由：当前页面为零条，空数据无法验证任何价格带判断。
- 2026-10-11：价格带保持运营配置而非硬编码或从第三方自动填充。理由：现行产品契约明确规定其来源和结论边界。
- 2026-10-11：官方物料准入和 SKU 详情核验分离。理由：前者可证明当前官方推广入口与公开推广价；后者只增强规格、库存和条件，不能以它的批量网络耗时阻塞公开优惠观察。
- 2026-10-11：价格带候选只从当前官方价格下调或可安全单券试算的可量化标题产生。理由：候选用于人工选择维护对象；它不是市场价样本，不能倒灌四档阈值或自动作出捡漏判断。
- 2026-10-12：自动核验页不再在用户 GET 请求上重跑 50 条验收实验。理由：该实验遍历全库且不改变任一机会的状态、价格或准入结论；用户需要的是最近自动核验快照及逐条理由，后者已有持久化数据。
- 2026-10-12：不引入完整结果集缓存。理由：本轮下推和重复遍历移除后，实际第二页已降至 1.07 秒；短时缓存会额外引入刷新一致性边界，当前无证据表明仍值得承担该复杂度。

## Idempotence and recovery

- 同一官方源可重复扫描；扫描以来源、外部键和指纹去重，原始扫描回执保留。
- 维护基准通过启停和版本审计修正，不删除历史基准记录。
- 如果回放缺少官方资格或 API 失败，记录具体错误并停止在来源审计，不把失败记录升级为优惠。
